# اجرای محلی لاگ مرکزی و نظرسنجی پیکو

تاریخ: ۲۴ اکتبر ۲۰۲۶. این تغییرات محلی هستند؛ استور، سرور، DNS و شاخهٔ main تغییر نکرده‌اند و commit/push انجام نشده است.

## اجرا

دو پروژه روی شاخهٔ `codex/monitoring-v1` هستند:

- افزونه: `C:/Users/User/Documents/GitHub/price-finder-extension`؛ مبنا `origin/develop` موجود (`c894ada`). فایل تحویلِ ثبت‌نشدهٔ مالک حفظ شده است.
- بک‌اند و پنل: `C:/Users/User/Documents/Codex/piqo-api`؛ مبنا شاخهٔ موجود دیوار (`1ab186b`) که تغییرات قبلی را حفظ می‌کند؛ بک‌اند شاخهٔ develop ندارد.

در پوشهٔ بک‌اند:

```powershell
npm install
npm --prefix admin install
npm run dev:monitoring
```

این دستور API را روی `http://127.0.0.1:3000` و پنل را روی `http://127.0.0.1:5173` بالا می‌آورد. فقط loopback؛ هیچ فایل env تولید را بار نمی‌کند و کلیدهای افیلیو و relay را وارد اجرای محلی نمی‌کند. حساب مالک با رمز تصادفی ساخته می‌شود؛ رمز را از `.local/owner-password.txt` بخوانید. این فایل و دیتابیس محلی در Git نادیده گرفته می‌شوند. رمز در چت یا خروجی فرمان چاپ نمی‌شود. توقف با Ctrl+C است.

روی این دستگاه Docker وجود ندارد؛ اجرای آماده از PGlite، موتور PostgreSQL تعبیه‌شده با دیسک پایدار، استفاده می‌کند. این جایگزین آزمون استقرار روی PostgreSQL مستقل نیست. برای PostgreSQL مستقل متغیر `MONITORING_DATABASE_URL` تنظیم شود و `MONITORING_LOCAL_DB` خالی بماند. فایل `docker-compose.monitoring.yml` مسیر سرویس و volume را آماده می‌کند؛ خودکار اجرا نشده است.

در پوشهٔ افزونه:

```powershell
npm run build:dev
```

در Chrome بخش Extensions، Developer mode را روشن و پوشهٔ `dist/dev` را با Load unpacked انتخاب کنید. در ساخت DEV فقط `PIQO_MONITORING_BASE_URL` به `http://127.0.0.1:3000` تغییر می‌کند؛ لاگ و نظرسنجی محلی می‌مانند. `PIQO_API_BASE_URL` برای جست‌وجوی افیلیو و دیوار روی `https://api.piqoo.ir` می‌ماند؛ سایر منابع هم مسیرهای قبلی خود را دارند. کلید تولید در بک‌اند محلی یا افزونه لازم نیست. اگر `/v1/search` را مستقیماً از API محلی بدون اعتبار افیلیو فراخوانی کنید، خطای `503 AFFILIO_NOT_CONFIGURED` طبیعی است؛ این مسیر دیگر مقصد جست‌وجوی نسخهٔ DEV نیست. نسخهٔ استور را جایگزین نکنید.

### اصلاح تفکیک مسیر جست‌وجو و مانیتورینگ — ۲۴ اکتبر

در نمونهٔ ماوس M171 (`dkp-141244`)، ساخت قبلی DEV تمام API پیکو را به بک‌اند محلی تغییر می‌داد. جست‌وجوی محلی `HTTP 503 / AFFILIO_NOT_CONFIGURED` می‌داد، در حالی که API اصلی برای `M171` پاسخ 200 داشت. این تغییر هنوز در کار محلی ثبت‌نشدهٔ مانیتورینگ بود؛ کامیت معرفی‌کننده برای bisect وجود ندارد و تغییرات مالک جابه‌جا نشدند.

آدرس‌های جست‌وجو و مانیتورینگ جدا شدند. تست `node test/build-endpoints.test.mjs` اسکریپت ساخت واقعی و مقداردهی diagnostics/survey را با فایل‌سیستم درحافظه‌ای برای dev/release بررسی می‌کند؛ بدون شبکه، زمان یا تصادف. تست قبل از اصلاح با مقدار اشتباه localhost برای جست‌وجو شکست خورد. کش جست‌وجو به V19 تغییر کرد تا نتایج ناقص ساخت قبلی دوباره خوانده نشوند؛ سابقه، لاگ‌ها و پاسخ‌های نظرسنجی حذف نمی‌شوند.

پس از ساخت تازه، کارت PIQO DEV در `chrome://extensions` را Reload و صفحهٔ محصول را Refresh کنید. لاگ‌های خطای قبلی تاریخی‌اند و حذف یا بازنویسی نمی‌شوند؛ یک جست‌وجوی تازه را بررسی کنید. پاسخ موفق API اثبات صحت همهٔ لینک‌ها یا قیمت‌ها نیست و این اصلاح الگوریتم ساخت/حفظ لینک افیلیو را عوض نمی‌کند.

## قرارداد و محدودیت‌ها

- `POST /v1/diagnostics/events`: حداکثر ۴۰ رویداد و ۳۲ KiB؛ پاسخ `accepted_ids` پس از پذیرش پایدار. تکرار event_id داده را تغییر نمی‌دهد. فیلد ناشناخته رد می‌شود.
- رویدادها: `search_started`، `request_finished`، `source_finished`، `results_presented`، `search_finished` و `search_linked`؛ قرارداد نسخهٔ ۱ در `diagnostics.js` و schema بک‌اند تعریف شده است.
- شناسهٔ search مستقل از شمارندهٔ تب است؛ درخواست مشترک فقط یک سری request دارد و مصرف‌کننده با network_search_id وصل می‌شود. کش دستگاه search جدیدِ درخواستی را ثبت می‌کند، اما درخواست شبکهٔ ساختگی نمی‌سازد. نمایش مجدد نتایج شناسه را عوض نمی‌کند.
- برای منابع JSON شناخته‌شده و Technolife ساختار پاسخ بررسی می‌شود. برای HTML بدون نتیجه و بدون قرارداد روشن، مقدار نامعلوم/parse_error استفاده می‌شود؛ صحت استخراج و قیمت با موفقیت شبکه یکی نیست.
- رویداد نمایش پس از دو فریم مرورگر، فقط با پنل قابل دیدن و نتایج غیرخالی تأیید می‌شود. اگر پنل دیده نشود، زمان اولین نمایش نامعلوم است. زمان دریافت سرور با زمان تجربهٔ کاربر یکی نیست.
- صف: سقف ۴۰۰ رویداد، عمر ۲۴ ساعت، ۵ تلاش، فاصلهٔ افزایشی و بررسی دقیقه‌ای با Chrome alarms. retry بعد از راه‌اندازی مجدد ادامه می‌یابد. این مسیر از لاگ محلی API کپی نمی‌کند.
- `POST /v1/surveys`: بله/خیر، توضیح اختیاری تا ۱۰۰۰ نویسه، نسخه، زمان و survey_id؛ بدون اتصال به جست‌وجو. retry همان پاسخ ثابت را می‌فرستد؛ پذیرش تکراری یک پاسخ می‌سازد.
- نظرسنجی پس از ۵ جست‌وجوی پایان‌یافته در ۳ روز تقویمیِ محلی، در پایان جست‌وجو پیشنهاد می‌شود؛ یک یادآوری پس از ۱۴ روز و حداکثر دو دعوت. لغو جست‌وجو شمرده نمی‌شود. حساب و تماس کاربر نداریم.
- APIهای `/v1/admin/*` نیازمند نشست مالک‌اند. GETها بدون ورود هم مسدودند؛ تغییرات نیاز به Origin معتبر و CSRF دارند. فیلترها: ۲۴ ساعت، ۷ روز یا ۳۰ روز، نسخه و منبع. فهرست‌ها صفحه‌بندی ۵۰تایی دارند.
- نرخ خطا: درخواست خطادار تقسیم بر نمونهٔ شبکه پس از کنارگذاشتن لغوها؛ پاسخ خالی خطا نیست. کش سرور از جدول شبکهٔ تازه جداست. دادهٔ قدیمی‌تر از ۱۵ دقیقه برچسب کهنه دارد. هیچ شاخصی ادعای صحت قیمت نمی‌کند.
- نام محصول، متن جست‌وجو، URL کامل، متن خطا، کوکی و شناسهٔ دائمی کاربر وارد دیتابیس مانیتورینگ نمی‌شوند. IP برای محدودیت نرخ در حافظه پردازش می‌شود؛ لاگ زیرساخت مستقل است.

## نگهداری، بکاپ و بازیابی

دادهٔ خام و نظر کاربران بر اساس received_at پس از ۳۰ روز، هنگام شروع و سپس روزانه پاک می‌شوند. اجرای روزانه ممکن است حذف را تا یک دوره دیرتر انجام دهد؛ مرورگر و سرور خاموش کاری اجرا نمی‌کنند. اعتبار ورود ۸ ساعت و سشن‌ها سمت سرورند.

CLI بک‌اند: `npm run monitoring -- migrate`، `cleanup`، `backup <directory>` یا `restore <file>`. بکاپ AES-256-GCM نیازمند `MONITORING_BACKUP_KEY` با ۶۴ رقم hex است؛ کلید را جدا از فایل بکاپ نگه دارید و در Git نگذارید. بکاپ رمز و نشست مدیر را شامل نمی‌شود؛ بازیابی دادهٔ منقضی را برنمی‌گرداند و received_at قبلی را حفظ می‌کند. فایل‌های بکاپ قدیمی‌تر از ۷ روز در اجرای backup حذف می‌شوند. با تنظیم `MONITORING_BACKUP_DIR` و کلید، اجرای روزانهٔ نگهداری بکاپ هم می‌گیرد؛ روی سرور هنوز فعال نشده است.

برای تغییر/بازیابی رمز مالک، رمز ۱۲ تا ۲۵۶نویسه‌ای از stdin به `npm run monitoring -- owner-password` داده شود؛ هرگز به‌عنوان آرگومان یا در تاریخچهٔ فرمان وارد نشود. تمام نشست‌ها با این کار باطل می‌شوند. فایل رمز اولیهٔ محلی پس از تغییر رمز باید جداگانه به‌روز/حذف شود. مسیر دیتابیس درست را در محیط CLI تنظیم کنید؛ هم‌زمان با اجرای PGlite به همان پوشه اتصال دوم باز نکنید.

## اعتبارسنجی و مرحلهٔ بعد

### جزئیات قابل‌فهم خطاها — ۲۰۲۶/۱۰/۲۵

در جدول سلامت منابع، «آخرین خطای ثبت‌شده» و در مسیر هر جست‌وجو، «جزئیات درخواست» اضافه شد. کد HTTP، کد کنترل‌شدهٔ خطا و راه بررسی نمایش داده می‌شود. آخرین خطا متعلق به بازه و فیلتر انتخاب‌شده است و سلامت لحظه‌ای سرویس را ثابت نمی‌کند.

نوع ساخت افزونه (DEV یا اصلی)، مقصد درخواست (API محلی، API اصلی پیکو یا منبع خارجی) و محیط سرور پنل جدا نمایش داده می‌شوند. DEV همچنان قیمت را از API اصلی می‌گیرد؛ ثبت لاگ DEV به API محلی می‌رود. اطلاعات ثبت‌نشدهٔ لاگ‌های قبلی «نامشخص» است؛ از HTTP 503 به‌تنهایی علت دقیق حدس زده نمی‌شود.

فیلدهای اختیاری جدید: `error_code`، `build_channel`، `target_environment` و `operation`. متن خام پاسخ، URL، نام محصول و عبارت جست‌وجو ذخیره نمی‌شوند. بررسی پاسخ خطای API پیکو به ۴ کیلوبایت و ۱۵۰ میلی‌ثانیه محدود است و پاسخ اصلی را مصرف نمی‌کند. برای فعال‌شدن، ابتدا بک‌اند جدید اجرا شود، سپس خروجی `dist/dev` در Chrome Reload و صفحهٔ محصول Refresh شود. تغییر پایگاه داده لازم نیست.

تست نمایش جدا از دیتابیس کاربر: پس از build پنل، `node test/admin-diagnostic-ui.test.mjs` در مخزن افزونه. تست با دادهٔ ساختگی روی پورت موقت، دسکتاپ و عرض ۳۷۵ را بررسی می‌کند.

تست‌های جدید افزونه: `npm run test:monitoring`؛ تست‌های قبلی: `npm test` و اسکریپت‌های مرتبط ناوبری/سایدبار. بک‌اند: `npm test`، `npm run typecheck`، `npm run build`؛ پنل: `npm --prefix admin run build`.

تست‌های خودکار، پذیرش تکراری، قطع ارتباط، راه‌اندازی مجدد صف، چند تب، درخواست مشترک، ثابت‌ماندن شناسه، انواع خطا، آستانه و یادآوری نظرسنجی، دسترسی غیرمجاز، CSRF، payload نامعتبر، پاک‌سازی و بازیابی رمزگذاری‌شده را پوشش می‌دهند. پنل با Chrome محلی در دسکتاپ و عرض ۳۷۵ بررسی شده است. نمونه‌های تست در دیتابیس تست جدا هستند؛ پنل اصلی با دادهٔ خالی شروع می‌شود.

قبل از سرور: آزمون PostgreSQL مستقل/Compose، ظرفیت، بودجه، تنظیم Origin و reverse proxy/TLS، نگهداری لاگ زیرساخت، محافظت کلید بکاپ و اجرای زمان‌بندی، آزمون مسیرهای واقعی منابع و تأیید انتشار سیاست حریم خصوصی لازم است. بررسی بیرونی خاموشی سرور، نمودار دسته‌ها، آمار کلیک و گزارش مشکل کارت جزو این فاز نیستند.


### نتیجهٔ اعتبارسنجی این تحویل

- ۱۹ تست بک‌اند پاس شد؛ typecheck و build بک‌اند و پنل پاس شدند. npm audit برای بک‌اند و پنل مورد شناخته‌شده‌ای گزارش نکرد.
- تست‌های لاگ/نظرسنجی و یکپارچگی background، مجموعهٔ اصلی افزونه و تست‌های مرورگری ناوبری و سابقه اجرا شدند.
- پنل با ورود واقعی محلی و چهار صفحه، حالت بدون داده، RTL و عرض ۳۷۵ بررسی شد؛ مشکل عرض محتوا و جهت سایدبار در بررسی تصویری اصلاح شد.
- فرم واقعی نظرسنجی با ماژول زمان‌بندی و API تست روی پورت تصادفی loopback و PostgreSQL جدا در حافظه بررسی شد: iframe مخفی دعوت مصرف نمی‌کند، پاسخ ناموفق خودکار ارسال نمی‌شود، retry همان پاسخ را می‌فرستد و موفقیت پس از تأیید سرور نمایش داده می‌شود. این داده‌ها وارد پنل اصلی نشده‌اند.
- نصب خودکار کل بستهٔ افزونه در Chrome نصب‌شده با روش Extensions.loadUnpacked در این محیط تکمیل نشد؛ آزمون کامل بسته با Load unpacked دستی هنوز انجام نشده است. تست منابع فروشگاهی زنده و PostgreSQL مستقل/Compose نیز انجام نشده‌اند.
- API و پنل اصلی محلی با دیتابیس پایدار PGlite بالا آورده شدند. سرور تست موقت پس از اعتبارسنجی متوقف می‌شود.

تست مستقل فرم: npm run test:survey-ui؛ خودش API و PostgreSQL موقت را روی پورت آزاد اجرا و متوقف می‌کند. در صورت جابه‌جایی بک‌اند، PIQO_BACKEND_DIR و برای مسیر Chrome، CHROME_PATH تنظیم شوند. این تست به سرویس اصلی محلی یا production داده نمی‌فرستد.


## افزودهٔ ۲۶ اکتبر ۲۰۲۶: استفادهٔ زنده و دسته‌ها

صفحهٔ /usage در پنل اضافه شد. GET /v1/admin/usage احراز هویت مالک دارد؛ فیلترهای days=1/7/30، version، build=dev/release/unknown و bucket=day/week را می‌پذیرد. جلسهٔ فعال، تعداد شناسه‌های موقت دیده‌شده در ۵ دقیقهٔ اخیر است؛ این عدد تعداد دقیق افراد نیست. پنل هر ۱۵ ثانیه و فقط در تب قابل دیدن به‌روز می‌شود و هنگام خطا عدد قدیمی را زنده معرفی نمی‌کند.

افزونه از chrome.storage.session استفاده می‌کند؛ شناسه بین تب‌ها و راه‌اندازی مجدد worker مشترک است، پس از ۳۰ دقیقه بی‌فعالیتی یا حداکثر ۸ ساعت می‌چرخد و با بسته‌شدن مرورگر از بین می‌رود. پنل قابل دیدن هر دقیقه پیام فعالیت می‌دهد؛ سمت worker پیام‌های نزدیک به هم محدود می‌شوند. POST /v1/usage/activity حداکثر ۱ KiB و بدون صف آفلاین است؛ پیام بیش از ۹۰ ثانیه قدیمی رد می‌شود تا اتصال دیرهنگام کاربر فعال ساختگی نسازد. دادهٔ حضورِ غیرفعال بیش از یک روز در پاک‌سازی روزانه حذف می‌شود و در بکاپ نیست.

دسته روی دستگاه و با قواعد محدود عنوان، نسخهٔ ۱، تعیین می‌شود؛ نام یا متن عنوان ارسال نمی‌شود. دسته‌ها: موبایل، لپ‌تاپ، لوازم کامپیوتر، صوتی، تلویزیون، لوازم خانگی، آشپزخانه، پوشاک، کفش، لوازم خودرو، ورزش، ابزار و نامشخص. عنوان چندمعنایی یا اکسسوریِ دستگاه، در نبود قاعدهٔ مطمئن، نامشخص می‌ماند. دسته، روش، اطمینان و نسخهٔ قواعد فقط در search_started همراه session_id موقت ثبت می‌شوند و با لاگ خام ۳۰ روز نگهداری می‌شوند. بدون LLM یا سرویس خارجی.

تعداد جست‌وجو با search_id یکتا حساب می‌شود، نه تعداد رویداد و نه کاربران یکتا. سهم دسته‌ها بر همهٔ جست‌وجوها شامل unknown است؛ لاگ قدیمی بدون دسته unknown محسوب می‌شود و از روی نام محصول بازسازی نمی‌شود. روند براساس زمان رخداد و منطقهٔ تهران است؛ هفته‌ها از دوشنبه آغاز می‌شوند و اولین بازه ممکن است ناقص باشد.

تست‌ها: npm run test:usage و npm run test:usage-ui در افزونه؛ test/usage.test.ts در بک‌اند. تست‌های کل بک‌اند (۲۲ مورد)، build/typecheck و بررسی موبایل/دسکتاپ پاس شدند. دادهٔ آزمایشی در دیتابیس کاربر وارد نشده است. برای دادهٔ جدید، پس از اجرای بک‌اند جدید و build:dev، افزونهٔ dist/dev در Chrome Reload و صفحهٔ محصول Refresh شود. نسخهٔ استور و سرور منتشر نشده‌اند.
