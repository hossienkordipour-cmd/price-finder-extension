# خلاصهٔ اتصال دیوار به پیکو

تاریخ ثبت: ۱۲ اکتبر ۲۰۲۶

این سند توضیح می‌دهد نتایج دیوار چگونه به پیکو اضافه شدند و چه کارهایی برای انتشار عمومی باقی مانده است. هیچ کلید مخفی‌ای در این فایل قرار ندارد.

## نتیجهٔ فعلی

- بک‌اند روی سرور ایران از مسیر Vercel به Divar MCP وصل شده است.
- جست‌وجوی سامسونگ A55 در سرور واقعی موفق بود؛ ۱۰ آگهی با نام، قیمت، تصویر و لینک برگشت.
- نمایش نتایج در افزونهٔ DEV با تست کاربر تأیید شد.
- انتشار همین تغییر در Chrome Web Store در این گفتگو تأیید نشده است؛ نسخهٔ DEV و نسخهٔ فروشگاه جدا هستند.

## مسیر دریافت اطلاعات

```text
افزونهٔ پیکو
  → https://api.piqoo.ir/v1/divar/search?q=نام‌محصول
  → بررسی کش Redis در بک‌اند
  → https://piqo-divar-relay.vercel.app/api/mcp
  → Divar MCP روی Cloudflare Workers
  → لیستینگ‌های عمومی دیوار
  → تبدیل نتیجه به قالب پیکو و نمایش در افزونه
```

نام محصول برای جست‌وجو ارسال می‌شود. کلید relay فقط در بک‌اند و تنظیمات Vercel قرار دارد و داخل افزونه نیست.

## چرا Vercel اضافه شد؟

ابتدا بک‌اند مستقیماً به `https://divar-mcp.mmdju2.workers.dev/mcp` وصل می‌شد. درخواست‌های سرور ایران به `/health` و `/mcp` پس از ۲۰ ثانیه بدون دریافت داده timeout شدند.

یک پروژهٔ آزمایشی به نام `piqo-mcp-test` روی Vercel ساخته شد. جست‌وجوی ثابت آیفون ۱۳ از آن موفق بود؛ همان endpoint از VPS ایران نیز پاسخ موفق داد. بنابراین مسیر ایران → Vercel → MCP قابل استفاده بود. علت دقیق اختلال مسیر مستقیم مشخص نشد.

پس از تست، پروژهٔ جداگانهٔ `piqo-divar-relay` برای درخواست‌های واقعی و احراز هویت‌شده منتشر شد. پروژهٔ آزمایشی، مسیر production نیست.

## رفتار relay و بک‌اند

- relay فقط درخواست `POST` با کلید معتبر را می‌پذیرد.
- کلید در Vercel با نام `PIQO_RELAY_TOKEN` و نوع Secret ثبت شده است.
- ابزار مجاز جست‌وجو `search_ads` است؛ درخواست‌های آغاز اتصال MCP نیز مجازند.
- شهر در relay فعلاً روی تهران ثابت است و فقط آگهی‌های دارای عکس درخواست می‌شود. نسخهٔ جدید کد سقف ثابت ۱۰ را حذف می‌کند: ۲۴ نتیجه در هر صفحه، حداکثر ۵ صفحه و پیش‌فرض ۶۰ آگهی غیرتکراری در بک‌اند. فعال‌شدن این تغییر نیازمند انتشار relay و بک‌اند است؛ [جزئیات و تست‌ها](DIVAR_PAGINATION_FIX_FA.md).
- relay امکان انتخاب آدرس سرویس مقصد یا اجرای ابزارهای دلخواه را به درخواست‌دهنده نمی‌دهد.
- بک‌اند از قیمت تومانی MCP استفاده می‌کند؛ آن را مجدداً از ریال تبدیل نمی‌کند.
- آگهی‌های بدون قیمت عددی مثبت، از جمله توافقی، و قیمت‌های دارای پرچم `price_is_placeholder` از نتایج مقایسه حذف می‌شوند.
- عنوان، قیمت، تصویر thumbnail و لینک آگهی به قالب افزونه تبدیل می‌شوند.
- فعلاً نتایج دیوار در قالب پیکو با `condition: used` نمایش داده می‌شوند؛ این برچسب، تشخیص قطعی وضعیت واقعی تک‌تک آگهی‌ها نیست.
- درخواست‌های هم‌زمان یکسان در همان فرایند بک‌اند مشترک می‌شوند و نتایج با کلید جداگانهٔ دیوار کش می‌شوند.
- تنظیم فعلی کش: تازه تا ۱۸۰ ثانیه، قابل استفاده همراه refresh پس‌زمینه تا ۹۰۰ ثانیه، و نتیجهٔ خالی تا ۶۰ ثانیه.
- اگر relay تنظیم نشده باشد، کد همچنان مسیر مستقیم MCP را استفاده می‌کند؛ fallback مستقیم به API دیوار پیاده‌سازی نشد.

## تنظیمات لازم

در `.env` بک‌اند روی سرور:

```dotenv
DIVAR_RELAY_URL=https://piqo-divar-relay.vercel.app/api/mcp
DIVAR_RELAY_TOKEN=کلید_مشترک_مخفی
```

در Environment Variables پروژهٔ Vercel:

```text
PIQO_RELAY_TOKEN = همان کلید مشترک بک‌اند
Environment = Production
Type = Secret
```

عبارت بالا فقط نمونه است؛ مقدار نمونه را به‌جای کلید واقعی وارد نکنید. کلید باید تصادفی و حداقل ۳۲ کاراکتر باشد. پس از تغییر تنظیمات Vercel، redeploy لازم است؛ پس از تغییر `.env` بک‌اند، کانتینر باید دوباره ایجاد شود. کلیدها را در Git یا فایل افزونه ثبت نکنید.

## به‌روزرسانی و تست روی سرور

دستورهای زیر را با کاربر `piqo` در ترمینال اجرا کنید، نه داخل فایل `.env`:

```bash
cd /home/piqo/piqo-api
git pull --ff-only origin main
docker compose up -d --build
curl -sS --get --data-urlencode 'q=سامسونگ A55' https://api.piqoo.ir/v1/divar/search
```

پاسخ موفق شامل `results` است. `meta.cache` می‌تواند `miss`، `fresh` یا `stale` باشد. آگهی‌ها ممکن است تغییر کنند یا حذف شوند؛ تعداد ثابت نتایج تضمین نیست.

برای بررسی خطا:

```bash
docker compose logs --tail=100 api
```

## تست افزونه و نکتهٔ build

در تست اول فقط شیپور نمایش داده می‌شد. علت این بود که سورس افزونه جدید بود، اما فایل تولیدشدهٔ `dist/dev/background.js` هنوز مسیر مستقیم قدیمی دیوار را داشت.

مشکل با اجرای دستور زیر برطرف شد:

```bash
npm run build:dev
```

سپس افزونهٔ PIQO DEV در `chrome://extensions` Reload و صفحهٔ محصول refresh شد؛ کاربر نمایش نتایج دیوار را تأیید کرد. برای دیدن آن‌ها، فیلتر «فقط نو» نباید فعال باشد.

Reload افزونه به‌تنهایی build جدید ایجاد نمی‌کند. نسخهٔ Chrome Web Store نیز به انتشار نسخهٔ جدید نیاز دارد.

## بررسی‌های انجام‌شده

- TypeScript بک‌اند بدون خطا بررسی شد.
- ۱۲ تست بک‌اند، از جمله ارسال کلید به relay، handshake و استفاده از پاسخ، پاس شد.
- دو تست relay برای رد درخواست بدون کلید و محدودکردن ابزار/شهر/تعداد پاس شد.
- تست واقعی بک‌اند محلی از relay: دریافت ۱۰ آگهی، وجود تصویر و پاسخ `fresh` برای جست‌وجوی تکراری.
- درخواست واقعی بدون کلید به relay رد شد.
- endpoint production از VPS ایران نتیجهٔ موفق داد.
- نسخهٔ DEV افزونه با تست کاربر تأیید شد.

## کارهای باقی‌مانده و محدودیت‌ها

1. کلید relay در اسکرین‌شات گفتگو دیده شد؛ باید با یک کلید جدید مشترک در Vercel و `.env` سرور تعویض شود. انجام این تعویض هنوز تأیید نشده است.
2. merge تغییر افزونه، افزایش شمارهٔ نسخه، ساخت release و انتشار در Chrome Web Store باید انجام/تأیید شود.
3. در جست‌وجوی A55 یک آگهی باتری نیز از MCP برگشت؛ کیفیت حذف لوازم جانبی با فیلتر تطبیق افزونه باید جداگانه بررسی شود.
4. داده‌ها از سرویس عمومی شخص ثالث می‌آیند. API مستندنشدهٔ دیوار و رفتار MCP ممکن است تغییر کند؛ سرویس MCP طبق مستندات بررسی‌شده محدودیت ۲۰ درخواست در دقیقه به‌ازای هر IP دارد. کش همهٔ محدودیت‌های ظرفیت را رفع نمی‌کند.
5. قیمت، موجودبودن آگهی و وضعیت واقعی کالا باید در صفحهٔ دیوار تأیید شود. لینک، تصویر یا حضور آگهی در نتایج به معنی تأیید فروشنده نیست.
