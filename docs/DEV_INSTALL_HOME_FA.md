# نصب نسخهٔ توسعهٔ پیکو روی Chrome سیستم خانه

تاریخ تهیه: ۱۴ اکتبر ۲۰۲۶

## هدف و اطلاعات پروژه

هدف، دریافت آخرین کد شاخهٔ `develop` و نصب محلی نسخهٔ `PIQO DEV` برای تست است؛ نه انتشار افزونه و نه تغییر نسخهٔ عمومی.

- مخزن: https://github.com/hossienkordipour-cmd/price-finder-extension
- شاخهٔ مورد استفاده: `develop`
- کامیت اصلاحات موجود هنگام تهیهٔ راهنما: `624865f`؛ اگر develop جلوتر رفته، آخرین نسخهٔ آن را دریافت کنید، نه اینکه به این کامیت برگردید.
- فرمان ساخت: `npm run build:dev`
- پوشهٔ قابل نصب: `dist/dev` در همان مخزن
- نام افزونه پس از ساخت: `پیکو | PIQO DEV — مقایسه قیمت`
- `dist` و `node_modules` در Git ذخیره نمی‌شوند؛ صرفاً Clone/Pull کردن، نسخهٔ قابل نصب DEV را نمی‌سازد.
- DEV اسم محیط توسعه است؛ ساخت آن شمارهٔ نسخه را خودکار به «۲» تغییر نمی‌دهد.

## متن آماده برای دادن به AI

> می‌خواهم نسخهٔ توسعهٔ افزونه پیکو را طبق این راهنما روی Chrome سیستم خانه نصب و بررسی کنی. مخزن price-finder-extension را پیدا کن یا در مسیر مورد تأیید من Clone کن؛ دستورهای AGENTS.md موجود را بخوان و وضعیت Git را بررسی کن. تغییرات محلی را حفظ کن. آخرین شاخه develop را دریافت کن، وابستگی‌ها را نصب کن، تست‌ها و build:dev را اجرا کن و پوشه dist/dev را برای Load unpacked آماده کن. اگر به ورود GitHub، نصب Node.js یا اقدام دستی در Chrome نیاز داری، همان مرحله را به من اعلام کن. main را تغییر نده، Force Push/Reset نکن، PR یا Merge انجام نده و چیزی روی سرور، Vercel یا Chrome Web Store منتشر نکن. در پایان شاخه، کامیت، نتیجه تست، مسیر خروجی و وضعیت واقعی نصب را گزارش بده؛ ساخت موفق را با نصب و تست واقعی در Chrome یکی ندان.

## مرحله ۱ — دریافت مخزن روی سیستم خانه

اگر GitHub Desktop نصب است:

1. وارد حسابی شو که به مخزن دسترسی دارد.
2. اگر مخزن را نداری، از `File → Clone repository` آن را Clone کن. اگر موجود است، همان را باز کن؛ Clone تکراری لازم نیست.
3. `Fetch origin` را بزن.
4. از `Current branch` شاخهٔ `develop` را انتخاب کن.
5. اگر `Pull origin` نمایش داده شد، آن را بزن.
6. با `Repository → Show in Explorer` مسیر محلی مخزن را پیدا کن. مسیر کامپیوتر محل کار الزاماً با مسیر خانه یکی نیست.

اگر تغییرات محلی ثبت‌نشده داری، قبل از جابه‌جایی شاخه یا دریافت کد توقف کن و آن‌ها را با تصمیم خودت حفظ کن؛ حذف، Reset یا Stash خودکار انجام نشود.

برای AI یا استفاده از Git در ترمینال، در ریشهٔ مخزن و پس از تأیید تمیز بودن وضعیت:

```powershell
git status --short
git fetch origin
git switch develop
git pull --ff-only origin develop
git branch --show-current
git log -1 --oneline
```

اگر شاخهٔ محلی develop وجود ندارد، به‌جای `git switch develop` اجرا کن:

```powershell
git switch --track origin/develop
```

اگر Pull به‌علت اختلاف تاریخچه متوقف شد، Force یا Reset نکن؛ اختلاف را گزارش بده. برای نصب DEV نیازی به Merge با main نیست.

## مرحله ۲ — نصب وابستگی‌ها و ساخت

Node.js و npm باید روی سیستم نصب باشند. اگر موجود نیستند، نسخهٔ LTS را از https://nodejs.org دریافت و نصب کن و سپس ترمینال جدید باز کن.

از ریشهٔ مخزن، PowerShell را باز کن و اجرا کن:

```powershell
node --version
npm.cmd --version
npm.cmd ci
npm.cmd test
npm.cmd run build:dev
```

در Windows از `npm.cmd` استفاده شده تا محدودیت اجرای `npm.ps1` مانع نشود؛ نیازی به ضعیف‌کردن Execution Policy نیست. در ترمینال‌های دیگر می‌توان از `npm` استفاده کرد.

هر فرمان باید موفق تمام شود. اگر خطا داشت، قبل از مرحلهٔ بعد علت را بررسی کن. `npm ci` وابستگی‌ها را از package-lock نصب می‌کند و برای نصب اولیه به دسترسی شبکه نیاز دارد؛ پوشهٔ node_modules محلی را دوباره می‌سازد.

در پایان ساخت باید پیامی شبیه این ببینی:

```text
Built PIQO DEV at ...\price-finder-extension\dist\dev
```

فایل `manifest.json` باید مستقیماً داخل `dist/dev` باشد. اسکریپت ساخت پوشهٔ خروجی قبلی `dist/dev` را جایگزین می‌کند؛ فایل شخصی داخل این پوشه نگذار.

برای نصب افزونه نیازی به اجرای بک‌اند، Docker، کپی `.env` یا کلید relay نیست. تنظیم API موجود در کد استفاده می‌شود؛ DEV افزونه لزوماً به معنی داشتن بک‌اند توسعهٔ مستقل نیست.

## مرحله ۳ — نصب در Chrome

1. در نوار آدرس Chrome، `chrome://extensions` را وارد کن.
2. `Developer mode` را روشن کن.
3. روی `Load unpacked` کلیک کن.
4. پوشهٔ `dist/dev` داخل همین مخزن را انتخاب کن؛ نه ریشهٔ مخزن و نه `dist/release`.
5. کارت افزونه با نام `PIQO DEV` باید ظاهر شود و روشن باشد.
6. اگر نسخهٔ اصلی پیکو هم نصب است، هنگام تست آن را موقتاً خاموش کن تا دو پنل هم‌زمان نمایش داده نشوند؛ حذف نسخهٔ اصلی لازم نیست.

مرجع نصب محلی و Reload: https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world

## مرحله ۴ — بررسی نصب

- یک صفحهٔ واقعی محصول یا آگهی را باز یا Refresh کن.
- پنل پیکو را باز کن و نام، عکس و قیمت همان محصول را بررسی کن.
- به محصول دیگری برو؛ پنل نباید محصول قبلی را نگه دارد.
- نتایج مرتبط و عملکرد مرتب‌سازی را بررسی کن.
- وجود `Errors` در کارت افزونه را بررسی کن؛ در صورت خطا، متن خطا و URL صفحه را ثبت کن، نه کلیدها یا اطلاعات ورود را.
- اگر ابزار AI محتوای پنل را نمی‌بیند ولی کاربر می‌بیند، این را محدودیت ابزار گزارش کن، نه تأیید خالی‌بودن پنل.

تست خودکار موفق، تضمین صحت همهٔ فروشگاه‌ها و همهٔ قیمت‌های زنده نیست. برای نتیجهٔ نصب واقعی باید کارت افزونه و محتوای پنل در Chrome بررسی شوند.

## دریافت تغییرات بعدی

روی develop، پس از حفظ تغییرات محلی:

```powershell
git pull --ff-only origin develop
npm.cmd ci
npm.cmd test
npm.cmd run build:dev
```

سپس در `chrome://extensions` روی دکمهٔ ↻ کارت `PIQO DEV` کلیک کن و صفحات محصول باز را Refresh کن. معمولاً نیازی به Remove و نصب دوباره نیست؛ مسیر پوشهٔ افزونه را ثابت نگه دار.

## خطاهای رایج

- **node/npm شناخته نمی‌شود:** Node.js را نصب کن یا بعد از نصب، ترمینال را دوباره باز کن.
- **دسترسی GitHub یا Clone ناموفق است:** ورود حساب و مجوز دسترسی به مخزن را بررسی کن؛ رمز یا Token را داخل چت نفرست.
- **dist/dev وجود ندارد:** ساخت موفق اجرا نشده یا ترمینال در ریشهٔ مخزن درست نیست.
- **Could not load manifest:** پوشهٔ انتخابی باید خودش manifest.json داشته باشد؛ dist/dev را انتخاب کن.
- **تغییرات جدید دیده نمی‌شوند:** شاخه develop، آخرین Pull، اجرای دوبارهٔ build:dev، Reload افزونه و Refresh صفحه را بررسی کن.
- **دو پنل پیکو دیده می‌شود:** نسخهٔ اصلی یا یک نصب DEV تکراری را هنگام تست خاموش کن.
- **قیمت‌ها یا نتایج نمی‌آیند:** نصب افزونه را از مشکل شبکه یا پاسخ سرویس جدا کن؛ بدون شواهد تنظیمات API یا کلیدها را عوض نکن.

## گزارش نهایی AI

در پایان این موارد را اعلام کن: مسیر مخزن، شاخه و کامیت دریافت‌شده، نتیجه npm ci و تست، نتیجه ساخت، مسیر دقیق dist/dev، اینکه نصب واقعاً انجام شد یا منتظر اقدام کاربر است، و نتیجه بررسی پنل. main و سرویس‌های production باید بدون تغییر باقی بمانند.
