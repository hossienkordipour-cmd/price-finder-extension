# بررسی امنیتی مرحله ۱۹

## دامنه و محدودیت

بررسی ایستای کد اجرایی شاخه develop و فایل‌های موجود در dist/dev انجام شد. بسته Release و ZIP نهایی هنوز ساخته نشده‌اند و باید جداگانه بررسی شوند. تست نفوذ، بررسی کامل سرور یا تضمین نبود آسیب‌پذیری انجام نشده است. هیچ کد اجرایی تغییر نکرد.

## یافته‌ها

- مهم: در sidebar/sidebar.js تابع generateCardHtml، نام محصول و فروشگاه، URL و تصویر بدون Escape در HTML قرار می‌گیرند. داده صفحه یا سرویس می‌تواند تگ یا ویژگی اضافی وارد کارت کند؛ امکان تغییر ظاهر یا مقصد لینک وجود دارد. اجرای JavaScript دلخواه با این بررسی اثبات نشده؛ محدودیت‌های CSP افزونه نیز همه انواع دست‌کاری HTML را برطرف نمی‌کنند. این همان اصلاح مرحله ۵ است که مالک قبلاً به تعویق انداخته است.
- مهم: parsePiqoApiResponse فقط غیرخالی‌بودن URL را بررسی می‌کند و کارت نیز پروتکل مقصد را محدود نمی‌کند. باید URL نهایی فقط http/https باشد؛ رفتار دقیق پروتکل‌های دیگر در مرورگر آزمایش نشده است. اصلاح قبلاً به تعویق افتاده است.
- کم‌خطر: شنونده CLOSE_PIQO_POPUP در content/content.js هویت فرستنده و origin را بررسی نمی‌کند. اسکریپت صفحه می‌تواند درخواست بستن پنل بدهد. در همین مسیر، فرمان دیگری یا دسترسی به داده مشاهده نشد.
- سازگاری/دفاع تکمیلی: کارت‌های target=_blank ویژگی صریح rel ندارند. این به‌تنهایی اثبات آسیب‌پذیری opener در Chrome مدرن نیست. تصویر خراب نیز به onerror درون HTML متکی است؛ محدودیت اجرای handler در صفحه افزونه می‌تواند مانع جایگزینی شود. اصلاح نیازمند تأیید است.
- کم‌خطر/دفاع تکمیلی: پیام‌های داخلی background نوع و اندازه همه فیلدهای محصول را اعتبارسنجی نمی‌کنند. نبود externally_connectable به معنای نبود مسیر مستقیم پیام از وب‌سایت عمومی است؛ پل سایت پیکو فقط روی دو origin مشخص و برای چهار عبارت ثابت فعال است. دورزدن این محدودیت یا بهره‌برداری عملی اثبات نشده است.

## موارد بررسی‌شده بدون یافته در دامنه بالا

- در فایل‌های اجرایی بررسی‌شده eval، new Function، importScripts یا script با منبع اینترنتی پیدا نشد؛ sidebar.js محلی است.
- مسیرهای فعال درخواست سرویس از HTTPS استفاده می‌کنند؛ http داخل namespace تصویر SVG، درخواست شبکه محسوب نمی‌شود.
- جست‌وجوی الگوهای رایج کلید خصوصی، توکن سرویس و رمز عبور در کد اجرایی و dist/dev نتیجه‌ای نداشت. این اسکن الگوهاست، نه تضمین کشف هر نوع راز. شناسه عمومی همکاری در فروش، راز احراز هویت محسوب نمی‌شود.
- dist/dev فقط فایل‌های runtime، تصاویر و فونت‌ها را دارد؛ node_modules، مستندات، فایل‌های Git و اسکریپت‌های قدیمی اصلاح در آن نبودند. ZIP کردن کل ریشه پروژه همچنان اشتباه است.
- SnappShop مستقیم و credentials: include در تابع باقی‌مانده دیده می‌شوند اما از جست‌وجوی فعال فراخوانی نمی‌شوند؛ نتایج افیلیو حفظ شده‌اند.
- لاگ‌ها و کش محلی همچنان مطابق گزارش داده‌ها هستند؛ اصلاح نگهداری مرحله ۷ قبلاً به تعویق افتاده و این بررسی آن را حل‌شده حساب نمی‌کند.

## نتیجه

اجرای بررسی مرحله ۱۹ تکمیل است، نه رفع همه یافته‌ها یا تأیید امنیت کامل. یافته‌های مهم نمایش HTML و URL همچنان باز هستند. تأیید انتشار فروشگاه قابل تضمین نیست. هر اصلاح فقط پس از توضیح و دریافت تأیید مالک انجام خواهد شد.
